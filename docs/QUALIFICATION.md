# Referral qualification and first conversation

Use an initial discussion to determine whether an introduction or a separately scoped technical assessment would help. Ask about the service problem, products in scope, timeline, geographic footprint, critical services, known provider notices, decision owner and procurement constraints. Do not request full number inventories, bills, credentials or configuration exports through public GitHub issues.

A qualified introduction has customer consent, a clear need, an authorized contact and a provider capable of assessing it. Share only the agreed minimum information through an approved channel. Avoid implying an existing provider appointment, guaranteed eligibility, a migration deadline, savings, or preferential access.

A technical assessment is a separate engagement: define scope, fees, access, confidentiality, deliverables, responsibility and acceptance before beginning. This repository demonstrates an approach; it is not a signed proposal or evidence of a completed customer deployment.

Suggested conversation opener: “I have worked on porting more than 20,000 numbers. I use a structured approach to inventory, dependencies, cutover planning and service continuity. This synthetic example shows that approach without disclosing customer information. If you are evaluating voice options, we can first establish scope and decide whether an introduction or a technical assessment is appropriate.”
