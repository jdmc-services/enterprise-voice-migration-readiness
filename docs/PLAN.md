# Project plan — illustrative 16-week envelope

These relative weeks show sequence and dependencies, not a promised completion time. Carrier lead times, specialty services, failed tests, and contract requirements can extend the envelope.

| Phase | Weeks | Evidence and exit gate |
| --- | --- | --- |
| Discovery and inventory | 1–3 | Customer-owned baseline, service classes, authorization and dependency owners |
| Provider and design assessment | 3–5 | Documented requirements, comparable offers, version-specific interoperability evidence |
| Readiness and rehearsal | 5–6 | Test plan, emergency-calling review, recovery paths, support coverage, approved change |
| Pilot: 100 IDs | 7 | Approved carrier order; acceptance evidence; explicit scale-up decision |
| Wave 2: 1,900 IDs | 8–9 | Pilot issues resolved and capacity confirmed |
| Wave 3: 4,000 IDs | 10–11 | Prior wave accepted and category-specific gates passed |
| Wave 4: 6,000 IDs | 12–13 | Same gates; staffing and carrier commitments reconfirmed |
| Wave 5: 8,000 IDs | 14–15 | Same gates; no forced scale-up to meet a date |
| Stabilization and closeout | 16 or later | Customer acceptance, support handover, bill reconciliation, authorized decommissioning |

The project manager maintains the [risk register](../data/risks.csv), dependency log, decision log, owner/date tracking, weekly sponsor review and change communications. Blocked items have a named owner and due date. Missing emergency-location evidence or uncertain recovery responsibility stops the affected migration; it is not averaged away in an overall readiness score.

Maintain a daily operational review during cutovers. Escalate critical service failures immediately through the approved incident process. The illustrative weeks in [wave data](../data/waves.csv) must be replaced by actual approved dates in a live engagement.
